# CLASS101 어드민 디자인 패턴 v2

CLASS101 Admin Figma의 패턴 원본(node `14919-97072`)에서 실측 추출한 규칙이다.
디자이너가 이 패턴을 복사해 화면을 그리듯, 어드민 화면을 만들 때 이 골격을 그대로 가져와 시작한다.
이 스킬은 자체 완결적이다 — 필요한 스펙은 전부 이 디렉토리의 `references/`에 있다.

## 작업 순서

1. **레퍼런스 읽기** (이 파일의 요약과 다르면 레퍼런스가 우선):
   - `references/layout.md` — 셸(헤더/사이드바/콘텐츠 영역), 콘텐츠 폭 패턴 5종, 페이지 헤더, 카드 해부도
   - `references/screen-types.md` — 화면 타입 3종(목록/폼/상세)의 완성 골격
   - `references/tokens.md` — 컬러/타이포/radius/레이아웃 토큰
2. **화면 타입 선택**: 요청된 화면을 목록 / 입력 폼 / 상세 중 가장 가까운 타입에 매핑한다.
   - 테이블 목록·대시보드 → `1열 full-width`
   - 입력·등록 폼 → `1열 max-720`
   - 상세 페이지 → `2열 4:8` (요약 카드 좌, 메인 우)
   - 그 외 일반 콘텐츠 → `1열 max-1312`, 주+보조 구성 → `2열 8:4`
3. **골격 조립**: 셸(헤더 72 / 사이드바 240 / 콘텐츠 패딩 40) → 페이지 헤더 → 카드 스택.
   임의로 새 레이아웃을 발명하지 않는다. 컴포넌트는 vibrant-ui(`@vibrant-ui/components`) 기준으로 명명한다.
4. **폰트 적용**: `references/tokens.md`의 "폰트 적용 규칙"을 그대로 따른다 — 프로젝트에
   Pretendard JP가 이미 로드돼 있는지 먼저 확인하고, 없으면 문서의 폴백 스택을 쓰며
   임의로 다른 폰트를 고르지 않는다. 폴백을 썼으면 결과물에 명시한다.
5. **산출물에 명시**: 사용한 폭 패턴 이름, 추정으로 채운 값(패턴에 없는 값), 폰트 폴백 여부를
   결과물과 함께 보고한다.

## 핵심 수치 요약

기준 뷰포트 1920. 셸: 헤더 72(전폭) + 사이드바 240(고정) + 콘텐츠 영역(1680, 좌우 패딩 40).

| 폭 패턴 | 컨테이너 | 콘텐츠 폭 | 컬럼 구성 |
|---|---|---|---|
| 1열 full-width | 1680 (가변) | 1600 | — |
| 1열 max-1312 | 1312 중앙 | 1232 | — |
| 1열 max-720 | 720 중앙 | 640 | — |
| 2열 8:4 | 1312 중앙 | 1232 | 주 808 + gap 40 + 보조 384 |
| 2열 4:8 | 1312 중앙 | 1232 | 보조 384 + gap 40 + 주 808 |

카드: 흰 배경 + 1px `outline2` 보더 + radius 8. 카드 간 수직 간격 기본 24(허용 20~28).
페이지 헤더: 상하 패딩 20, 제목 20/26 Bold, 우측 버튼 그룹(gap 8, 높이 38, primary가 맨 오른쪽).
컬러 요점: primary `#FF5D00`, 본문 텍스트 `#0C0C0C`, 보조 텍스트 `#949494`, 활성 메뉴 배경 `#F3F3F3`.
폰트: Pretendard JP — 적용 방법(기존 프로젝트 확인 → 폴백 스택)은 반드시 `references/tokens.md`의
"폰트 적용 규칙"을 참고한다. 임의로 다른 폰트를 고르지 않는다.

## 예외 프로토콜 (필수)

패턴은 작업을 효율화하는 도구일 뿐이며, 화면 특성상(특히 **상세 페이지**) 예외가 필요할 수 있다.
패턴을 벗어나야 더 효과적이라고 판단되면 **임의로 어기지 말고** 아래 절차를 따른다:

1. 셸(헤더/사이드바/콘텐츠 패딩 40)과 콘텐츠 폭 패턴은 끝까지 유지하려고 시도한다.
   예외는 가능한 한 카드 내부 구성·컬럼 폭 조정 수준으로 국한한다.
2. 그래도 어겨야 한다면, 작업 확정 **전에** 보고한다:
   - **어길 규칙**: 규칙 이름과 기준값 → 제안값 (예: "보조 컬럼 384 → 480")
   - **이유**: 왜 패턴 준수 버전이 비효과적인지
   - **대안 비교**: 패턴 준수 버전으로 만들면 어떻게 되는지 한 줄
3. 대화형 세션이면 AskUserQuestion 등으로 승인을 받고 진행한다.
   비대화형(원격/자동) 작업이면 패턴 준수 버전을 기본으로 만들고, 산출물에
   "예외 제안" 섹션으로 위 내용을 보고해 사용자가 결정하게 한다.
4. 승인된 예외는 반복될 가능성이 있으면 이 스킬의 레퍼런스에 반영할지 제안한다.

참고: Figma 원본 자체에도 허용된 변주가 있다 — 상세 페이지 예시는 보조 컬럼을 384 대신 420으로
쓴다(`references/screen-types.md`). 이 범위 안의 조정은 예외 보고 없이 가능하다.
