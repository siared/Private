## 0. 이 프로토타입의 실제 구조

6개 화면이 "플로우 1~5"로 묶여 있지만, **성격이 서로 다른 3종류가 섞여 있다.**

| # | 파일 | 실제 성격 | 보는 사람 | 레이아웃 기준 |
|---|---|---|---|---|
| — | `index.html` | 리뷰 허브 (목차) | 내부 팀 | 문서 |
| 1 | `mail.html` | **스펙 검토 문서** (AS-IS/TO-BE 대조표) | 내부 팀 | 문서 |
| 2 | `calendar.html` | **크리에이터 대면 제품 화면** | 외부 크리에이터 | 제품 |
| 3 | `remind.html` | **스펙 검토 문서** | 내부 팀 | 문서 |
| 4 | `premeeting.html` | **크리에이터 대면 제품 화면** | 외부 크리에이터 | 제품 |
| 5 | `meeting.html` | **내부 어드민 화면** | BD 매니저 | `docs/layout-patterns.md` 적용 대상 |

`checklist.html` · `manager.html`은 `meeting.html`로 보내는 리다이렉트 스텁이다.

**이 분류가 감사의 출발점이다.** 지금은 셋이 같은 톤·같은 카드·같은 오렌지로 그려져 있어서,
리뷰어가 "이건 문서다 / 이건 진짜 화면이다"를 구분할 단서가 없다.
4·5번만 `디자이너` 뱃지가 붙어 있지만, 실제로 디자인 부채가 가장 큰 건 **2번(캘린더)**과 **5번(매니저 뷰)**이다.

## P0 — 먼저 고치지 않으면 다른 판단이 전부 틀어지는 것

### P0-1. 폰트가 로드되지 않는다 (전 화면)

`vibrant-ds/colors_and_type.css`가 `fonts/PretendardJP-*.woff2` 9개를 `@font-face`로 선언하는데,
**zip 안에 `vibrant-ds/fonts/` 디렉토리 자체가 없다.**

```
vibrant-ds/
  assets/          ← 로고 2개만 있음
  colors_and_type.css
```

결과: 전부 시스템 기본 산세리프로 폴백된다. Pretendard JP의 타이트한 음수 자간(-0.768px 등)이
적용되지 않은 상태로 보고 있으므로, **지금 화면에서 내린 자간·굵기·줄바꿈 판단은 전부 무효다.**
폰트부터 붙이고 다시 봐야 한다.

### P0-2. 디자인 시스템이 장식으로만 붙어 있다

모든 페이지가 `colors_and_type.css`를 로드해 놓고, 바로 아래에서 자기만의 `:root`를 다시 선언한다.

```css
/* 6개 파일 전부 이렇게 시작한다 */
:root { --ink:#171717; --mute:#747474; --line:#e5e5e5; --biz:#ff5d00; ... }
```

DS에는 이미 `--primary`(#ff5d00), `--fg1`, `--fg2`, `--outline2`, `--neutral-90`이 정의돼 있다.
지금 구조에서는 **DS 토큰 값을 바꿔도 화면이 1px도 안 바뀐다.** 디자이너가 손댈 지렛대가 없는 상태.

부수 증상:
- `--ink:#171717`은 `--neutral-10`인데, DS의 본문 색 토큰은 `--fg1` = `--neutral-5`(#0c0c0c)다. 값이 다르다.
- `--mute:#747474`(`--neutral-50`)를 쓰지만 DS의 보조 텍스트는 `--fg2` = `rgba(55,55,55,.8)`다.
- `meeting.html`은 `--ok:#078641`을 직접 박았다. DS엔 `--success`가 있다.

### P0-3. 타이포 스케일이 임의값이다

DS는 `.ty-title4`(20/26) `.ty-body2`(14/18) `.ty-body4`(12/16) 같은 완결된 스케일을 제공하는데,
프로토타입에는 **단 한 번도 쓰이지 않았다.** 대신 이런 값들이 쓰인다:

- 크기: 26 / 22 / 20 / 16 / 15 / 14.5 / 13.5 / 12.5 / 11.5 / 10.5px — **0.5px 단위가 6종**
- 굵기: 650 / 750 / 800 / 850 — Pretendard는 100 단위 9웨이트다. **650·750은 존재하지 않아 브라우저가 임의 반올림한다.**
  DS가 정의한 건 400/500/600/700/800.

### P0-4. 배경색이 페이지마다 다르다 (이유 없음)

| 화면 | body 배경 |
|---|---|
| index | `#fafafa` |
| mail | `#f3f3f3` |
| calendar | `#faf6f1` (크림) |
| remind | `#f3f3f3` |
| premeeting | `#f7f7f7` |
| meeting | `#fafafa` |

플로우를 1→5로 넘기면 배경이 4번 바뀐다. 크림색(캘린더)만 의도가 읽히고 나머지 3종은 구분 의미가 없다.
`docs/layout-patterns.md` §5는 "전체가 흰 배경"이다.

## P1 — 화면별 구조 문제

### 2번 · `calendar.html` (크리에이터 대면 · 실제로 가장 취약)

`디자이너` 뱃지가 안 붙어 있지만, 전환율에 직접 닿는 유일한 화면이다.

1. **첫인상이 죽은 화면이다.** 3열(280 / 1fr / 300) 중 3열은 날짜를 고르기 전까지
   `opacity:.4; pointer-events:none`이다. 화면의 30%가 회색으로 비활성 상태로 시작한다.
2. **8월·9월 두 달을 동시에 펼친다.** 예약 가능일이 15 + 9 = **24개의 오렌지 동그라미**로 한꺼번에 나온다.
   우선순위가 없어서 "언제가 제일 빠른가"를 눈으로 스캔해야 한다. Calendly/Cal.com이 한 달만 보여주는 이유.
3. **1:1 ↔ 설명회 선택이 날짜 뒤에 숨어 있다.** 이 화면의 진짜 결정은 미팅 *유형*인데,
   좌측 설명 박스 2개로만 안내되고 실제 선택은 3열 안쪽 그룹 헤더로 들어간다.
   두 유형의 가능 슬롯이 다르면 **"고른 날짜에 원하는 유형이 없는" 막다른 길**이 생긴다.
   → 유형 → 날짜 → 시간 순으로 뒤집는 게 맞는지 검토 필요.
4. **내부 데이터가 그대로 노출된다.** 슬롯 캡션 `0/1`, `2/5`, `1/5`.
   크리에이터에게 `0/1`은 아무 의미가 없다. "예약 가능" / "3자리 남음" 같은 언어로 바꿔야 한다.
5. **타임존 표기가 없다.** 해외 크리에이터가 들어오면 그대로 사고다.
6. **예약 후가 없다.** `confirm` 클릭 시 초록 텍스트 한 줄(`toast`)만 뜨고 끝.
   확인 화면 / 캘린더 등록(.ics) / 취소·변경 경로가 전부 비어 있다.
7. **목업 스캐폴딩이 제품 카피에 섞여 있다.** 좌측 3번째 박스의
   "← 좌측 문구·구성에 의견 달기 (+)"는 리뷰어용 안내인데 크리에이터용 설명 박스와 같은 모양으로 놓여 있다.

### 4번 · `premeeting.html` (미팅 전 랜딩)

1. **게이트가 두 겹이다.** `mf-auth.js`의 @101.inc 게이트를 통과하면
   곧바로 페이지 자체의 "크리에이터 센터 로그인" 모달(`#gate`)이 또 뜬다.
   리뷰어는 모달을 연속 2번 닫아야 콘텐츠를 본다.
2. **가치를 보여주기 전에 로그인을 요구한다.** 뒤 콘텐츠는 `filter:blur(2.5px)`로 가려져 있다.
   크리에이터는 *무엇을 위해* 로그인하는지 모르는 상태로 결정해야 한다.
   (게다가 블러 처리된 DOM은 스크린리더에 그대로 읽힌다.)
3. **미팅 참여 버튼에 이중 잠금이 걸려 있다.** `loggedIn && watched` —
   이미 예약을 마친 사람에게 10~15분 영상 시청을 강제한다. 실제로는 재생 누르고 자리를 뜨는
   행동만 유발하므로 **아무것도 측정하지 못하면서 마찰만 만든다.**
4. **정보 우선순위가 뒤집혀 있다.** 커리큘럼이 9챕터 × 4강 = **36행 + 분 단위 뱃지**로 깔린다.
   이건 *강의를 살 사람*을 위한 판매 페이지 패턴이다.
   이 크리에이터는 *강의를 만들* 사람이고, 필요한 건 "15분 동안 무엇을 논의하는가"다.
5. **가격 카드가 화면에서 제일 시끄럽다.** 오렌지 풀필 배경에 99,000 / 149,000원.
   아직 존재하지도 않는 강의의 가격이 h1(이것도 오렌지)보다 눈에 먼저 들어온다.
6. **`docs/layout-patterns.md` §5 위반 — 오렌지가 6군데.** h1 · 태그칩 · 가격 블록 · 참여 버튼 ·
   메모 저장 버튼 · 재생 버튼. 규칙은 "primary는 화면당 핵심 CTA 1개".
   지금은 진짜 CTA인 [화상 미팅 참여하기]가 시각적 우위를 전혀 못 가진다.
7. **가장 중요한 요소가 가장 안 보인다.** 우측 sticky 열 = 영상(16:9) + 참여 + 메모 ≈ 600px 이상.
   1440×900 노트북에서 **메모 입력창은 접힘선 아래**다.
   그런데 이 메모가 5번 매니저 화면으로 넘어가는 유일한 데이터다.

### 5번 · `meeting.html` (매니저 뷰 · 어드민)

**여기가 `docs/layout-patterns.md`를 적용해야 하는 유일한 화면인데, 전혀 따르고 있지 않다.**

| 항목 | 문서 규칙 | 현재 |
|---|---|---|
| 셸 | 헤더 72 + 사이드바 240 + 콘텐츠 패딩 40 | 없음. `.bar` 40px 한 줄뿐 |
| 폭 패턴 | 상세 페이지 = `2열 4:8` (좌 384 / 우 808, 거터 40) | `max-width:720` 1열 |
| 페이지 헤더 | 높이 86 + ← + 타이틀 20px Bold + 우측 액션 | 없음 |
| 카드 radius | 16 | 14 |
| 카드 간격 | 28 | 12 |

구조 문제:
1. **메모가 348px 상자에 갇혀 있다.** `.grid`가 1fr/1fr인데 래퍼가 720px이므로 각 열 348px.
   미팅에서 가장 가치 있는 콘텐츠(크리에이터가 직접 쓴 메모)가 `min-height:64px` 박스에 들어가고,
   체크박스 5개가 720px 전폭을 쓴다. 완전히 뒤집혀 있다.
   → `2열 4:8`로 가면 좌 384에 기본정보/연동상태, 우 808에 메모 + 체크리스트가 자연스럽게 앉는다.
2. **체크 상태가 저장되지 않는다.** `localStorage` 저장 코드가 없다.
   미팅 도중 새로고침 한 번이면 체크가 전부 날아간다. 프로토타입이라도 이건 시연 중에 터진다.
3. **"영상" 태그는 죽어 있다.** `#tVideo`를 켜는 코드가 어디에도 없다.
   `premeeting.html`에서 `watched` 플래그를 저장하지 않기 때문에 원천적으로 알 수 없다.
4. **동료가 남긴 질문("읽기 모드 / 체크 모드를 나눌까")은 타당하다.**
   지금은 한 화면에 3가지 밀도가 섞여 있다 — 읽는 것(메모) · 확인하는 것(연동 상태) · 조작하는 것(체크).
5. **`.badge`가 클릭 영역 안에 있다.** `<label>`이 체크박스와 뱃지를 함께 감싸므로
   "필수"라는 *상태 표시*를 눌러도 체크가 토글된다. 상태인지 버튼인지 모호하다.

### 1·3번 · `mail.html` / `remind.html` (스펙 검토 문서)

1. **AS-IS와 TO-BE의 형식이 달라서 대조가 안 된다.**
   좌측은 원문 프롬프트 420자 잘린 덩어리 + `<details>` 전문,
   우측은 "유지/변경" 불릿 리스트. 서로 다른 장르라 눈으로 diff할 수가 없다.
   "무엇이 바뀌는가"가 목적이면 **필드 단위 변경표**(CTA / 미팅타입 / optional / 링크)가 맞다.
2. **탭이 접근 불가다.** `role="tablist"` 없음, 키보드 이동 없음, `aria-selected` 없음.
3. **`remind.html` 기본 탭 선택이 취약하다.** `if (i === 1)`이 **필터 전 인덱스**를 쓴다.
   `ORDER`의 앞쪽 항목이 데이터에 없으면 아무 탭도 선택되지 않아 **빈 화면**이 된다.
   (`show()`는 필터 후 인덱스를 쓰므로 두 곳의 기준이 다르다.)
4. **플로우가 미팅에서 끝난다.** `meeting-reminders.js`에는 `rate` · `plan` · `noshow`가 들어 있는데
   `FOCUS` 배열에서 제외돼 화면에 안 나온다. 미팅 후 단계(평가·기획안·노쇼)가 통째로 비어 있고,
   `/proposal`이 말하는 T1–T7 중 T6·T7이 프로토타입에 없다.

### 허브 · `index.html`

1. 5개 스텝이 **성격 구분 없이 같은 카드**로 나열된다 (§0 표 참조). 문서 2개와 화면 3개가 섞여 있다.
2. 각 페이지의 `.bar` 내비게이션이 제각각이다 — `mail`은 다음만, `calendar`는 ←/→,
   `meeting`은 "처음으로". **현재 위치를 보여주는 진행 표시가 없다.**

## P2 — 접근성 · 크래프트

1. **포커스 상태가 전무하다.** `.day` `.slot` `.tabs button` `.chap summary` `.mf-pin` 전부
   커스텀 스타일인데 `:focus-visible` 정의가 한 곳도 없다.
2. **캘린더가 키보드로 조작 불가다.** 날짜가 `<div class="day">` + click 핸들러다.
   `role`·`tabindex`·`aria-pressed` 없음. 탭으로 날짜에 도달할 방법이 없다.
3. **색만으로 상태를 구분한다** (문서 §5 위반).
   `.day.avail` = 오렌지 테두리 + 오렌지 글자, `.slot.on` = 오렌지 테두리.
   규칙은 "색 점 + 텍스트 라벨 동반".
4. **터치 타겟이 작다.** `.day`는 `padding:8px 0` ≈ 30px 높이. 권장 44px 미만.
5. **저대비 소형 텍스트.** `.hint`·`.src`·`.cap`이 11.5px `#747474`.
   `#f7f7f7` 위에서 약 4.3:1 — 11.5px에서는 읽기 부담이 크다.
6. **코멘트 핀이 콘텐츠를 덮는다.** `.mf-pin`이 `top:8px; right:8px` 절대배치라
   `.col.tobe`에서는 "TO-BE" 라벨 줄 위에 올라앉고, 비교 행마다 핀이 2개씩 뜬다.
7. **radius가 표류한다.** 10 / 12 / 14 / 16 / 20 / 99px 혼용. 토큰은 4 / 8 / 16 / 20 / full.
8. **반응형이 끊긴다.** `calendar.html`은 960px에서 3열 → 1열로 한 번에 떨어진다.
   태블릿 구간(768~960)에서 슬롯 열이 화면 맨 아래로 밀려 날짜-시간 연결이 끊긴다.

## 어디부터 손댈지 — 3가지 트랙

세 트랙은 독립적이라 어느 것부터 시작해도 된다.

### 트랙 A · 기반 정리 (P0)
폰트 연결 → 페이지별 `:root` 제거하고 DS 토큰으로 통일 → 타이포 스케일/웨이트 정규화 → 배경 단일화.
**화면 구조는 안 건드리고 "제대로 보이는 상태"를 먼저 만드는 작업.**
이걸 먼저 하면 이후 모든 시각 판단이 신뢰할 수 있게 된다. 6개 화면 전부 영향.

### 트랙 B · 매니저 뷰 재설계 (5번)
`docs/layout-patterns.md`의 **상세 페이지 = 2열 4:8** 골격으로 재구축.
어드민 셸(헤더 72 / 사이드바 240 / 페이지 헤더 86) 적용,
좌 384에 기본정보·연동상태, 우 808에 메모(주인공) + 체크리스트.
읽기/체크 모드 분리 여부 결정 + 체크 상태 영속화.
**저장소 규칙이 명확히 적용되는 유일한 화면이라 정답에 가장 빨리 도달한다.**

### 트랙 C · 크리에이터 여정 재설계 (2·4번)
캘린더의 유형-먼저 순서 전환 + 단일 월 + 내부 수치 제거 + 예약 확인 단계 신설,
랜딩의 게이트 제거(또는 뒤로 미루기) + 커리큘럼 → 미팅 아젠다로 전환 + 메모 승격.
**리스크가 가장 크고 제품 결정이 섞여 있어서, 손대기 전에 합의가 필요한 구간.**

## 문서화되지 않은 미결 사항

- **1:1과 설명회의 가능 슬롯이 같은 날짜 집합인가?** 다르다면 캘린더는 유형 우선 구조여야 한다.
- **미팅 전 영상 시청을 정말 강제할 것인가?** 지금 게이트 로직의 근거가 프로토타입에 없다.
- **크리에이터 센터 계정 연동을 미팅 *전*에 받을 것인가, 미팅 *중*에 매니저가 유도할 것인가?**

- **미팅 후 단계(T6·T7)** 화면이 없다. 이번 범위에 포함할지.
