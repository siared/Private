## 0. AS IS 정리 (Figma에서 확인한 사실)

**스테퍼 4단계**: ① 강의 기획안 → ② 테스트 영상 → ③ 강의 제작 → ④ 런칭 예약
(뒤 단계는 자물쇠 아이콘 = 순차 해금)

| 단계 | 화면 구성 |
|---|---|
| ① 강의 기획안 | AI 기획안 추천 배너 + 기본 정보 폼 + 커리큘럼(강의별 상태: 검토 대기 / 검토 중 / 개선 필요 / 승인) |
| ② 테스트 영상 | 안내 카피 + `테스트 영상 TIP` 아코디언 + 강의 1개 선택 + 영상 업로드(FHD 16:9) → 제출 후 "영상 검토 중 99%" |
| ③ 강의 제작 | 좌측 서브내비(강의 목록 / 클래스 소개 / 크리에이터 소개 / 클래스 제작 가이드) + 진행률 카드 "전체 검토 승인까지 40개 남음 (승인 0개 / 총 40개)" + 챕터·강의 리스트 |
| ④ 런칭 예약 | (잠금) |

**전환 순간**: "검토 승인 완료! 이제 다음 단계를 준비해볼까요?" 모달 → `검토 기준 보기` / `나중에`.
이때 CS 채팅(해피 bottom sheet)이 함께 뜬다. 우하단에는 플로팅 버튼 2개(가이드 문서 · 해피)가 상시 존재.

**이미 만들어져 있는 미팅 자산** (재사용 가능, 새로 만들 필요 없음)
- 예약 화면: 월 캘린더 + 슬롯 리스트, `1:1 기획 상담(15분)` / `그룹 설명회(30분·최대 5명, 정원 표시)`, 미팅 1시간 전 Google Meet 링크 안내
- 미팅 상세(대기실): 담당자 · 일시 + `변경` · `미팅 5분 전부터 참여 가능` · 자주 묻는 질문 · **"궁금한 점 물어보기" 텍스트 입력 + 파일 첨부(자동 저장)**
- 변경 / 취소 플로우 완비

### 문제 정의 3가지

1. **알림이 겹치고, 타이밍이 어긋난다.** 축하 모달과 CS 채팅이 동시에 뜬다. 게다가 "검토 기준"은 **승인 직후 1회성**으로 주어지는데, 정작 필요한 건 그 뒤 작업하는 내내다. 지금 구조는 "가장 안 읽을 시점에 가장 중요한 정보를 주는" 형태.
2. **막혔을 때의 출구가 텍스트 챗봇뿐이다.** 특히 단계가 새로 열릴 때 "이 단계에서 뭘 어디까지 해야 하지?"라는 벽이 가장 크고, 이건 글보다 말로 5분 듣는 게 빠르다.
3. **시간 축이 없다.** 진행률이 "40개 중 0개"라는 **개수**로만 존재한다. 크리에이터에겐 언제까지라는 기준이 없어 추진력이 안 생기고, 매니저는 "느린 사람"과 "이탈한 사람"을 구분할 신호가 없다.

## 1. 유사 사례 리서치

| 사례 | 우리가 가져올 것 |
|---|---|
| **Amazon KDP 사전 예약(pre-order)** — 출시일을 저자가 직접 걸고, **1회에 한해 최대 30일 무패널티 연기**, 그 이상 어기면 1년간 사전 예약 금지 ([정책](https://kdp.amazon.com/en_US/help/topic/G201499480)) | 마감일 변경을 **막지 말고 등급화**하라. 1회차 무마찰 → 2회차부터 사유 수집 → 3회차부터 매니저 개입. "약속"의 무게는 유지하면서 컨택 비용은 0으로. |
| **Fiverr 납기 연장 요청** — 주문 목록에서 `Request Extension` 버튼 → 연장 일수 + 사유 메시지 → 상대가 수락/거절 ([설명](https://fiverrpromotion.net/blog/how-to-extend-delivery-date-on-a-fiverr-order/)) | **버튼 하나 + 일수 + 사유**라는 최소 구성. 다만 우리는 승인 대기를 두지 말고 즉시 반영(매니저에겐 알림만)으로 더 가볍게. |
| **Ariely & Wertenbroch (2002), 자기부과 마감일** — 사람들은 스스로 비용 있는 마감일을 걸고, 그것이 미루기를 줄인다. 단 **스스로 정한 마감일은 균등 분배된 외부 마감일보다 성과가 낮다** ([논문](https://web.mit.edu/ariely/www/MIT/Papers/deadlines.pdf)). 2026년 [재현 연구](https://journals.sagepub.com/doi/10.1177/09567976261460772)에서는 효과가 재현되지 않음 | **하이브리드**: 시스템이 균등 분배한 추천 일정을 기본값으로 채워두고, 크리에이터는 조정만 한다. 동시에 재현 실패 사례가 있으니 **효과를 과신하지 말고 A/B로 검증**. |
| **Udemy 강사 플로우** — 제출 전 [Course Quality Checklist](https://support.udemy.com/hc/en-us/articles/229604988-Udemy-Course-Quality-Checklist)를 상시 문서로 제공, 대시보드에서 제작 단계 내비게이션 | 검토 기준은 "한 번 보여주는 모달"이 아니라 **상시 접근 가능한 체크리스트**가 업계 표준. |
| **인프런 강의 제출** — 제출 후 최대 7영업일, 수정 필요 시 **별도 연락** ([가이드](https://inflab-1.gitbook.io/inflearn/course-open/submit)) | 우리의 "검토 중 99%"는 이미 인프런보다 낫다. 남은 격차는 *검토 후 커뮤니케이션*이 제품 밖(메일/채팅)으로 새는 것 → 우측 패널로 흡수. |
| **Drift / Intercom Fin** — 챗봇이 답을 못 하거나 좌절·반복 루프를 감지하면 사람에게 에스컬레이션하고, **대화 중 캘린더로 바로 미팅을 잡게** 한다. 이때 대화 맥락 전체가 함께 넘어간다 ([정리](https://inquirly.ai/blog/ai-automation/chatbot-to-human-handoff/)) | 해피의 역할 재정의: 답변자가 아니라 **미팅으로 가는 최단 경로**. 그리고 **맥락 자동 첨부**가 핵심. |
| **Cal.com inline embed** — 서드파티로 이동시키지 않고 흐름 안에 예약 위젯을 심으면 전환이 오른다 ([문서](https://cal.com/embed)) | 케어 미팅 예약은 별도 페이지 이동이 아니라 **우측 패널 안 인라인 예약**으로. |

## 2. 제안 A — 승인 모달은 축하만, 검토 기준은 우측 상시 패널 (의견 1)

원칙: **"축하는 순간, 기준은 상시."**

### A-1. 승인 모달 정리
- CS 채팅 자동 오픈 **제거**. 모달과 채팅이 동시에 뜨지 않게 한다.
- 모달은 축하 + 다음 행동 1개만:
  - 타이틀: `검토 승인 완료! 이제 ②테스트 영상 단계예요`
  - 본문: 다음 단계에서 할 일 한 줄 + **추천 마감일 한 줄** (예: "보통 7일 정도 걸려요")
  - Primary: `다음 단계 시작하기` / Secondary(텍스트): `15분 안내 미팅 잡기` / Tertiary: `나중에`
- `검토 기준 보기` 버튼은 없앤다 — 기준은 다음 화면에서 항상 보이므로.

### A-2. 우측 상시 패널 (Docked Side Panel, 폭 320~360)
다음 단계 화면에 진입하면 패널이 **첫 진입 1회만 펼침** 상태로 나타나고, 이후에는 접힘/펼침 상태를 기억한다.

```
┌─ 스테퍼 ①─②─③─④ ────────────────────────────────┬──────────────┐
│                                                  │  [체크리스트]  │
│   (기존 콘텐츠 폭 680 유지, 좌측 여백을 줄여 패널 확보)      │   검토 기준   │
│                                                  │   도움받기     │
│                                                  │              │
│                                                  │  ▢ 촬영 구도  │
│                                                  │  ▣ FHD 16:9  │
│                                                  │  ▢ 자막       │
└──────────────────────────────────────────────────┴──────────────┘
```

- **탭 3개**
  - `체크리스트` — 이 단계 필수 항목. 시스템이 판정 가능한 항목(해상도·길이·첨부 유무)은 **자동 체크**, 나머지는 수동 체크. 상단에 `n/m 완료` 프로그레스.
  - `검토 기준` — 반려 사유 Top 5 + 통과 예시 / 실패 예시 이미지 비교. 텍스트 규정집이 아니라 **눈으로 비교되는 형태**.
  - `도움받기` — 해피에게 묻기 / **케어 미팅 예약(인라인)** / 가이드 문서.
- **컨텍스트 전환**: 강의 리스트에서 특정 강의를 선택하면 패널이 그 강의의 반려 사유·개선 요청으로 바뀐다 (Figma 인스펙터·Linear 상세 패널과 같은 방식). 지금 제품 밖(메일/채팅)으로 새던 피드백이 작업 화면 안으로 들어온다.
- **접힘 상태**: 우측에 아이콘 레일(체크·기준·도움)만 남는다. **지금의 우하단 플로팅 버튼 2개(가이드 문서·해피)를 이 레일에 통합**해 화면 우하단 중복을 정리한다.
- **반응형**: 1440 이상은 push(콘텐츠 밀기), 1280 이하는 overlay로 전환.

> 대안으로 "모달 안에 기준을 다 넣기"도 가능하지만, 읽어야 할 시점이 작업 중이라는 점에서 패널을 권장한다.

## 3. 제안 B — 케어 미팅 신청 (의견 2)

이미 있는 예약/변경/취소 플로우를 **그대로 재사용**하고, 제작 플로우 쪽에 **진입점과 맥락 전달**만 새로 만든다.

### B-1. 진입점 4곳 (상시 1 + 문맥 3)

| # | 위치 | 트리거 | 카피 예시 |
|---|---|---|---|
| 1 | 우측 패널 `도움받기` 탭 / 접힘 레일 캘린더 아이콘 | 상시 | `막히셨나요? 15분 통화로 풀어드릴게요` |
| 2 | **승인 모달의 세컨더리 CTA + 다음 단계 진입 상단 배너(1회성)** | 단계 전환 | `②테스트 영상, 뭘 준비할지 15분만에 설명드릴게요` |
| 3 | 해피가 먼저 말 걸기 | 막힘 감지 (아래) | `이 부분 두 번째 개선 요청이네요. 담당 매니저와 15분 통화 잡아드릴까요?` |
| 4 | 해피 답변 하단 | `해결이 안 됐어요` 클릭 | `사람에게 물어볼까요?` |

**막힘 감지 트리거** (3번용)
- 같은 강의에 `개선 필요` 2회 이상
- 단계 마감 D-3인데 진척률 0%
- 7일 무활동
- 체크리스트 항목을 3일 이상 체크하지 못한 상태

사용자가 짚은 "단계 하나 패스할 때 구두 설명이 필요하다"는 니즈는 **2번**이 정확히 대응한다.

### B-2. 미팅 타입 3종 (기존 컴포넌트 재사용)

| 타입 | 길이 | 아젠다 | 비고 |
|---|---|---|---|
| 단계 오리엔테이션 | 15분 | 단계별 고정 아젠다 자동 세팅 | 현재 단계에 따라 자동 선택 |
| 1:1 케어 | 30분 | 자유 주제 + 반려 사유 자동 첨부 | 기존 `1:1 기획 상담` 확장 |
| 그룹 오피스아워 | 30분 | 주 1회 공통 Q&A | 기존 `그룹 설명회(최대 5명)` 컴포넌트 그대로 |

### B-3. 차별점 — 맥락 자동 첨부
예약 시 **현재 단계 / 대상 강의 / 반려 사유 / 미충족 체크리스트 항목**이 자동으로 담겨, 이미 만들어져 있는 미팅 상세의 **"궁금한 점 물어보기"에 프리필**된다. 크리에이터는 상황을 다시 설명하지 않고, 매니저는 사전 준비 없이 들어와도 맥락을 안다.

미팅이 끝나면 매니저가 남긴 액션 아이템이 **우측 패널 체크리스트에 To-do로 꽂히고**, 필요하면 마감일 재조정을 함께 제안한다. 미팅이 일회성 상담이 아니라 **작업 화면에 남는 결과물**이 된다.

### B-4. 예약 UX
- 전면 페이지 이동 없이 **우측 패널 안 인라인 예약**: 가까운 3일치 슬롯만 노출 → `다른 날짜 보기`로 기존 전체 캘린더 화면 진입.
- 즉시 확정(매니저 승인 대기 없음), 기존 `미팅 5분 전 참여` · `변경/취소` 흐름 그대로 연결.
- 매니저 부하 관리: 해피가 1차 필터, 정형 15분 미팅과 그룹 오피스아워로 수요 흡수.

## 4. 제안 C — 단계별 마감일 (의견 3)

### 설계 원칙 3가지
1. **추천값은 시스템이, 확정은 크리에이터가.** 균등 분배된 추천 일정을 기본값으로 채워두고 조정만 하게 한다(리서치의 하이브리드 결론).
2. **약속하는 순간을 만든다.** 단계 진입 시 "일정 정하기" 1스텝. 스킵 가능하되, *스킵하면 추천 일정이 그대로 적용됨*을 명시한다.
3. **변경은 쉽게, 흔적은 남게.** 버튼 하나로 바꾸되 사유는 남는다. 매니저 컨택은 불필요.

### C-1. 화면 반영

**(a) 스테퍼에 날짜 얹기** — 각 스텝 라벨 아래 `~8/20`, 현재 스텝은 `D-5` 배지. 지연이면 경고색 `D+3`.

**(b) 진행률 카드 확장** — 기존 "전체 검토 승인까지 40개 남음" 카드 우측에 마감 블록 추가.

```
┌────────────────────────────────────────────────────────────┐
│ 전체 검토 승인까지 40개 남음        │  이 단계 마감 8/20 (D-5) │
│ 시작이 반이에요. 차근차근 가볼까요?    │  하루 4개씩이면 맞출 수  │
│ ▇▇▇▁▁▁▁▁▁▁  승인 0개 / 총 40개    │  있어요   [일정 변경]    │
└────────────────────────────────────────────────────────────┘
```

`하루 4개씩이면 맞출 수 있어요` 같은 **페이스 라인**이 핵심이다. 진행 단위가 이미 개수(40개)라 계산이 가능하고, 이 한 줄이 마감일을 *위협*에서 *가이드*로 바꾼다.

**(c) 일정 변경 시트** — 새 날짜 선택 + 사유 선택(촬영 일정 지연 / 개인 사정 / 기준을 잘 모르겠음 / 기타) + `이 단계 미팅도 잡기` 체크박스.
사유가 `기준을 잘 모르겠음`이면 미팅 CTA를 강조한다. 사용자가 원한 "매니저 컨택 없이 소통"이 되면서, 매니저에게는 **이탈 사유 데이터**가 쌓인다.

**(d) 변경 등급화 (KDP 방식)**

| 변경 횟수 | 동작 |
|---|---|
| 1회차 | 무마찰. 사유 선택만, 즉시 반영 |
| 2회차 | 사유 필수 + 매니저 알림 |
| 3회차 이상 또는 D+7 초과 | 매니저 컨택 / `보류` 상태 전환 제안 |

**(e) 알림** — D-3 · D-day · D+3 (앱 · 카톡 · 메일). D+3 알림에는 미팅 제안을 붙인다.

### C-2. 추천 일정 산출 (기본값 제안, `TODO(브랜드)` 실데이터로 보정 필요)

| 단계 | 기본 소요 |
|---|---|
| ① 강의 기획안 | 7일 |
| ② 테스트 영상 | 7일 |
| ③ 강의 제작 | 강의 수 × 0.5일 (40강 → 20일) |
| ④ 런칭 예약 | 3일 |

**런칭일 역산 모드**도 함께 제안한다. "언제 런칭하고 싶으세요?"를 먼저 물어 목표일을 받고 단계별로 균등 분배하면, 리서치가 가장 효과적이라고 본 형태(균등 분배)에 가장 가깝고 동기 부여도 크다.

### C-3. 매니저용 상태 정의 (어드민)

| 상태 | 조건 |
|---|---|
| 정상 | 마감일 이내 |
| 지연 | D+1 ~ D+6 |
| 위험 | D+7 이상 또는 일정 변경 3회 이상 |
| 중단 추정 | 14일 무활동 |

어드민 목록 화면은 저장소 규칙에 따라 **1열 full-width(콘텐츠 1600)** 테이블 목록 패턴으로 만든다 (`docs/layout-patterns.md`).

## 5. 세 제안이 하나로 묶이는 지점

우측 패널이 허브가 된다.

| 탭 | 답하는 질문 |
|---|---|
| 체크리스트 + 마감일 | **지금 뭘 해야 하고, 언제까지?** |
| 검토 기준 | **어느 수준까지 해야 통과하지?** |
| 도움받기 (해피 · 케어 미팅) | **막히면 누구한테?** |

세 질문의 답이 한 화면에 상주하면, 승인 모달은 축하만 해도 충분해진다.

## 6. 리스크와 완화

| 리스크 | 완화 |
|---|---|
| 마감일 압박이 오히려 이탈을 가속 | 톤을 "마감"이 아니라 "약속"으로. 변경 무마찰. `D+` 지연 표기를 크리에이터에게도 보여줄지는 A/B |
| 미팅 예약 증가로 매니저 부하 | 15분 정형 미팅 · 그룹 오피스아워로 흡수, 해피 1차 필터, 슬롯 상한 |
| 우측 패널이 좁은 화면에서 작업 영역 압박 | 1280 이하 overlay 전환, 접힘 상태 기억 |
| 자기부과 마감일 효과 자체가 불확실 (2026 재현 실패) | 추천 일정(외부 기준) 기본값 + 실험으로 검증 |

## 7. 성공 지표

- 단계별 완주율 / 단계별 실제 소요일 (중앙값)
- 케어 미팅 예약률 → **미팅 후 7일 내 다음 단계 진입률**
- 일정 변경 후 새 마감일 준수율
- 반려 재발률(같은 강의 2회 이상 개선 필요 비율) — 우측 패널의 실효성 지표
- 승인 모달 CTA 클릭률 (현재 `검토 기준 보기` 대비)
- 중단 추정 조기 발견 리드타임 (매니저 관점)

## 8. 실행 순서

| 릴리즈 | 범위 |
|---|---|
| 1차 | 승인 모달 정리(CS 채팅 분리) + 우측 패널(체크리스트 · 검토 기준) + 도움받기 탭에 기존 미팅 예약 연결 |
| 2차 | 단계별 마감일 (설정 · 표시 · 페이스 라인 · 변경 · 알림) + 어드민 상태 필터 |
| 3차 | 맥락 자동 첨부, 막힘 감지 트리거, 미팅 액션 아이템 → 체크리스트 연동 |

## 9. 확인이 필요한 것

1. 마감일 기준을 **단계별 소요일 누적**으로 잡을지, **런칭 목표일 역산**으로 잡을지 (둘 다 지원하되 기본값을 골라야 함)
2. 마감일 미준수에 계약상 실제 페널티가 있는지 (있다면 카피 톤이 달라짐)
3. 케어 미팅 담당자가 기존 미팅과 동일한 제작팀인지, 별도 케어 담당인지 (슬롯 풀 분리 여부)
4. 우하단 플로팅 버튼(해피 · 가이드)을 우측 패널 레일로 흡수해도 되는지 — 다른 페이지와 공유되는 전역 컴포넌트일 가능성
