현재 상태

AS IS에서 확인한 것

4단계 스테퍼(강의 기획안 → 테스트 영상 → 강의 제작 → 런칭 예약)에 순차 해금 구조. 3단계에는 좌측 서브내비와 “전체 검토 승인까지 40개 남음” 진행률 카드, 강의별 상태 검토 중 개선 필요 승인 이 이미 있다.

검토가 승인되면 “검토 승인 완료! 이제 다음 단계를 준비해볼까요?” 모달이 뜨고 검토 기준 보기 / 나중에 를 준다. 이때 CS 채팅(해피)이 함께 열린다. 우하단에는 가이드 문서·해피 플로팅 버튼 2개가 상시 떠 있다.

미팅 쪽은 이미 자산이 충분하다. 캘린더 + 슬롯 예약(1:1 15분 / 그룹 설명회 30분·정원 5명), Google Meet 연동, 변경·취소 플로우, 그리고 미팅 상세의 “궁금한 점 물어보기” 입력 + 파일 첨부까지 만들어져 있다. 케어 미팅은 새로 만드는 게 아니라 제작 플로우 쪽에 진입점과 맥락 전달만 붙이는 일이다.

문제 01 · 타이밍 가장 안 읽을 때 가장 중요한 걸 준다

축하 모달과 CS 채팅이 동시에 뜬다. 검토 기준은 승인 직후 1회성으로 주어지는데, 정작 필요한 건 그 뒤 작업하는 내내다.

문제 02 · 출구 막혔을 때 나갈 문이 챗봇뿐

새 단계가 열릴 때 “뭘 어디까지 해야 하지?”가 가장 큰 벽이고, 이건 글보다 말로 5분 듣는 게 빠르다.

문제 03 · 시간 진행률은 개수뿐, 날짜가 없다

“40개 중 0개”만 있다. 크리에이터에겐 추진력이, 매니저에겐 느린 사람과 이탈한 사람을 가를 신호가 없다.

제안 A · 의견 1

축하는 순간, 기준은 상시

승인 모달은 축하와 다음 행동 하나만 남기고, 검토 기준은 작업 화면에 상주하는 우측 패널로 옮긴다.

승인 모달 정리

  • CS 채팅 자동 오픈 제거. 모달과 채팅이 동시에 뜨지 않는다.
  • 타이틀: “검토 승인 완료! 이제 ②테스트 영상 단계예요” — 다음 단계에서 할 일 한 줄 + 추천 마감일 한 줄.
  • Primary 다음 단계 시작하기 / Secondary 15분 안내 미팅 잡기 / Tertiary 나중에.
  • 검토 기준 보기 버튼은 삭제 — 다음 화면에서 항상 보이니까.

  • 체크리스트 — 해상도·길이·첨부처럼 시스템이 판정 가능한 항목은 자동 체크, 나머지는 수동. 상단에 n/m 완료.
  • 검토 기준 — 반려 사유 Top 5 + 통과/실패 예시 이미지 비교. 규정집이 아니라 눈으로 비교되는 형태.
  • 도움받기 — 해피에게 묻기 / 케어 미팅 인라인 예약 / 가이드 문서.
  • 컨텍스트 전환 — 강의 행을 선택하면 패널이 그 강의의 반려 사유로 바뀐다. 지금 메일·채팅으로 새던 피드백이 작업 화면 안으로 들어온다.
  • 우하단 정리 — 플로팅 버튼 2개(가이드·해피)를 이 레일에 흡수해 중복을 없앤다.
  • 반응형 — 1440↑ push, 1280↓ overlay.

제안 B · 의견 2

케어 미팅은 만드는 게 아니라 연결하는 일

예약·변경·취소·사전 질문 입력은 이미 다 있다. 새로 만들 건 진입점 4개와 맥락 자동 첨부다.

차별점

예약할 때 맥락이 따라간다. 현재 단계 · 대상 강의 · 반려 사유 · 미충족 체크리스트가 자동으로 담겨, 이미 만들어져 있는 미팅 상세의 “궁금한 점 물어보기”에 프리필된다. 크리에이터는 상황을 다시 설명하지 않고, 매니저는 준비 없이 들어와도 맥락을 안다.

미팅이 끝나면 화면에 남는다. 매니저가 남긴 액션 아이템이 우측 패널 체크리스트에 To-do로 꽂히고, 필요하면 마감일 재조정을 함께 제안한다. 일회성 상담이 아니라 작업 화면에 남는 결과물이 된다.

예약 UI는 전면 페이지 이동 없이 패널 안 인라인으로. 가까운 3일치 슬롯만 보여주고 다른 날짜 보기에서 기존 캘린더 화면으로 넘긴다. 즉시 확정, 기존 5분 전 참여·변경/취소 흐름에 그대로 연결. 매니저 부하는 해피 1차 필터 + 정형 15분 + 그룹 오피스아워로 흡수한다.

제안 C · 의견 3

마감일은 위협이 아니라 페이스

추천값은 시스템이 균등 분배해 채워두고, 확정은 크리에이터가 한다. 변경은 버튼 하나로 쉽게, 대신 흔적은 남는다.

전체 검토 승인까지 33개 남음 시작이 반이에요. 차근차근 가볼까요?
승인 7개총 40개
이 단계 마감 8/20 · D-5 하루 4개씩이면 맞출 수 있어요

기존 진행률 카드 우측에 붙는 마감 블록. 진행 단위가 이미 개수라 페이스 계산이 되고, 이 한 줄이 마감일을 가이드로 바꾼다.

화면 반영

  • 스테퍼에 날짜 — 각 스텝 아래 ~8/20, 현재 스텝은 D-5, 지연이면 D+3.
  • 일정 변경 시트 — 새 날짜 + 사유(촬영 일정 지연 / 개인 사정 / 기준을 잘 모르겠음 / 기타) + 이 단계 미팅도 잡기 체크박스. 사유가 “기준을 잘 모르겠음”이면 미팅 CTA를 강조한다. 매니저 컨택 없이 소통되고, 매니저에겐 이탈 사유 데이터가 쌓인다.
  • 알림 — D-3 · D-day · D+3. D+3 알림에는 미팅 제안을 붙인다.

대안 · 런칭일 역산 모드

“언제 런칭하고 싶으세요?”를 먼저 물어 목표일을 받고 단계별로 균등 분배하는 방식. 리서치가 가장 효과적이라고 본 형태(균등 분배 외부 마감일)에 가장 가깝고 동기 부여도 크다. 둘 다 지원하되 어느 쪽을 기본값으로 둘지 결정이 필요하다.

통합

우측 패널이 허브가 된다. 세 질문의 답이 한 화면에 상주하면, 승인 모달은 축하만 해도 충분해진다.

  1. 마감일 기준을 단계별 소요일 누적으로 잡을지, 런칭 목표일 역산으로 잡을지 — 둘 다 지원하되 기본값을 골라야 한다.
  2. 마감일 미준수에 계약상 실제 페널티가 있는지. 있다면 카피 톤이 완전히 달라진다.
  3. 케어 미팅 담당자가 기존 미팅과 같은 제작팀인지, 별도 케어 담당인지 — 슬롯 풀 분리 여부.
  4. 우하단 플로팅 버튼(해피·가이드)을 패널 레일로 흡수해도 되는지 — 다른 페이지와 공유되는 전역 컴포넌트일 가능성.
