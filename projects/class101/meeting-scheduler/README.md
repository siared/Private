# 미팅 예약 캘린더 (Calendly 대체) — 미팅 생성 플로우 디자인

- PRD: https://app.notion.com/p/class101/3b8f558da4b3806488e8d9d5d86e1d6a
- 기준 문서: `docs/layout-patterns.md`, `tokens/tokens.md` (vibrant-ui 실측 토큰)
- 기준 뷰포트 1920 · 셸 공통(헤더 72 / 사이드바 240 / 콘텐츠 패딩 40)

## 플로우와 화면 구성

```
[01 메인] ──새 미팅 만들기──▶ [02 폼+미리보기] ──일정 설정하기──▶ [03 미연동이면 연동 유도]
   ▲                                                                │ 연동 완료
   └────────── 미팅 생성 완료 (토스트 + 목록/확정 일정 갱신) ◀── [04 슬롯 자동 생성·조정]
```

| 파일 | 화면 | 페이지 타입 / 폭 패턴 |
|---|---|---|
| `01-meeting-list.html` | 메인 — 생성된 미팅 리스트 + 확정된 스케줄 | 일반 콘텐츠 → **1열 max-1312** (콘텐츠 1232) |
| `02-meeting-create.html` | 새 미팅 만들기 — 입력 폼 + 실시간 미리보기 | **2열 8:4** (주 808 폼 + 보조 384 미리보기) |
| `03-slot-connect.html` | 일정 설정 진입 시 구글 캘린더 미연동 상태 — 연동 유도 모달 | 04와 동일 골격 + 모달 오버레이 |
| `04-slot-editor.html` | 미팅 일정(슬롯) 자동 생성 + 조정 주간 캘린더 | 캘린더(테이블형 전폭) → **1열 full-width** |

## PRD 반영 사항

- **폼 항목**: 미팅 제목 / 설명 / 소요 시간(10·15·20·30·60·90·120분) / 참여자 수 /
  유형(온라인=구글 밋 자동, 오프라인=장소 입력 노출) — 02번 카드 1.
- **예약 폼 질문**: 기본 1~4(크리에이터 센터 계정 로그인 시 이름·이메일·연락처 자동 입력) 고정 +
  추가 질문(Single/Multi Select · Text · 파일 첨부) 자유 구성 — 02번 카드 2.
- **예약 완료 후**: 기본 확인 페이지 또는 특정 URL 리다이렉트 — 02번 카드 3 (PRD 4항).
- **슬롯 입력은 폼 마지막**: 02번 카드 4(필수)에서 [일정 설정하기]로 진입.
  미연동이면 03(연동 유도 모달, "연동하지 않으면 활성화 불가" 명시), 연동돼 있으면 04로.
- **슬롯 자동 생성·조정(04)**: 가용 시간(평일 10–18) 내 빈 시간에 소요 시간 단위로 슬롯 자동 생성.
  구글 캘린더 기존 일정은 회색 블록으로 표시·자동 제외, 슬롯은 ✕로 제외(쉬는 시간 확보) /
  드래그로 이동 / 제외 슬롯 "다시 열기". **다른 미팅에 잡힌 예약은 빗금 블록**으로 표시해
  "가용 시간은 담당자 단위" 정책(A미팅 예약 시 B미팅에서 해당 시간 미노출)을 시각화.
- **메인(01)**: 미팅 카드 스택(카드 1개 = 미팅 1개) + 다가오는 확정 일정.
  카드에 활성/비활성 토글(비활성 시 공유 링크로 접속해도 예약 화면 미노출), 공유 링크 복사,
  열린 슬롯·확정 예약 수, 일정 관리 진입. 하단에 확정 일정(구글 캘린더 동기화), 생성 완료 토스트.
- 헤더 우측 상태 필로 캘린더 연동 상태 표시(연동됨=success / 미연동=neutral) — 토큰 만료·해제
  알림 요구사항의 상시 노출 지점.

## 패턴 선택 근거 및 예외 제안

- **01번이 목록인데 1열 full-width가 아닌 max-1312를 쓴 이유**: 담당자 1인이 만드는 미팅은
  많아야 5~10개 수준이라 테이블(검색·필터·페이지네이션)과 상단 지표 Stats Bar가 과하다고 판단해
  둘 다 뺐다. 테이블이 없어지면 full-width(1600)를 쓸 이유가 사라지므로 패턴 5종 중
  "그 외 일반 콘텐츠 → 1열 max-1312"로 내리고, 본문은 문서의 기본 단위인 **카드 수직 스택**
  (카드 1개 = 미팅 1개, 간격 20)으로 구성했다. 상태 필터만 섹션 헤더 우측 칩으로 남겼다.
  - 미팅 수가 수십 개 규모로 늘어나면 목록 타입(1열 full-width + Table)으로 되돌리는 것이 맞다.
- **02번이 폼인데 1열 max-720이 아닌 2열 8:4를 쓴 이유**: 요구사항에 "폼과 미리보기"가
  함께 명시되어, 패턴 5종 중 "주+보조 구성 → 2열 8:4"에 매핑했다(새 레이아웃 발명 아님).
  폼 행 규격(Label top + TextField lg 50, 행 간 16, 카드 간 28)은 폼 패턴 그대로 유지.
  - *패턴 준수(max-720) 대안*: 미리보기를 별도 버튼/모달로 빼면 1열 max-720으로 가능하나,
    입력-미리보기 실시간 대조가 끊긴다. 반복 채택 시 이 구성을 docs에 반영할지 제안함.
- **04번 캘린더를 full-width로**: 주간 7컬럼 그리드는 테이블형 전폭 콘텐츠로 보고
  목록 타입(1열 full-width)에 매핑했다.

## 패턴에 없어 임의로 정한 값

- 캘린더: 시간축 폭 60 / 1시간 행 높이 56 / 30분 슬롯 칩 높이 26 / 슬롯 옅은 배경 `#FFF7F2`
  (primary의 tint, 토큰에 없음)
- 모달(03): 폭 420, radius 16(토큰 `xl`), 스크림 `rgba(0,0,0,0.4)`
- 미리보기 프레임(02) 내부 축소 스케일의 타이포·간격
- 로고: 이미지 에셋(165×22) 부재로 텍스트 로고 대체
