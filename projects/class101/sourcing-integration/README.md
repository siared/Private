# 소싱 통합 1차 — 화면 디자인

PRD: "소싱 통합 1차 — 공유 요약 (범위·DB·일정)" 기반. `docs/layout-patterns.md` +
`tokens/tokens.md`의 CLASS101 Admin 패턴을 적용한 HTML 목업.

## 화면 구성

| 파일 | PRD 범위 | 페이지 타입 | 폭 패턴 |
|---|---|---|---|
| `design/01-list.html` | P0 통합 리스트 (+그룹 담기 진입) | 목록 | 1열 full-width (1600) |

## PRD 필드 매핑

- **목록 테이블**: TrackingCode(활동명 하단 캡션) / Name(마스킹) / Status(색점 셀렉트 필) /
  BD Owner / 채널(태그 칩) / 최근 발송 내역(말줄임) / 발송 타입(BDC·700·프리미엄 칩) /
  최근 발송일(기본 정렬 ↓, 3개월+ 경과 시 경고 뱃지) / 최근 메모(말줄임)
- **통계 바**: 전체 / 담당자 소통중 / 수신거부 / 크리에이터 연결됨 / 검토 필요 / 미매칭 —
  P1 정합성 등급을 목록 진입 시점에 보이게 배치
- **그룹(캠페인)**: 행 선택 시 검색 행 우측에 "N건 선택됨 · 그룹에 담기 ▾" 일괄 액션 노출
- **상세 좌측(4fr)**: 기본 정보(마스킹 해제 액션) → 소스 정보(utmSource·link·description) →
  크리에이터 연결(매칭 등급 뱃지 + 근거 캡션, 클래스·총 정산금액) → 미팅(Calendly 연동)
- **상세 우측(8fr)**: 컨택 히스토리 타임라인 — 이메일 발송(type·message_id·From) /
  메모 / 미팅을 유형 칩으로 구분. 상단 상태 카드에 최초·마지막 발송일 + 수신거부 여부

## 문서에 없어서 임의로 정한 것 (확인 필요)

1. **등록일·수정일 컬럼은 목록에서 기본 숨김** — 컬럼 12개는 과밀이라 9개로 추림.
   컬럼 설정 기능으로 노출한다고 가정
2. **트래킹 코드 자동 발급** — 수동 등록 폼에 TrackingCode 입력란 대신
   "저장 시 자동 발급" 안내 문구 (API upsert 기준 식별자라 수동 입력 배제)
3. **통계 바의 세그먼트 구성** — PRD에 명시 없음. Status 2종 + 매칭 등급을 조합
4. **"그룹에 담기" 액션 위치** — 템플릿에 일괄 액션 사례가 없어 검색 행 우측에 배치.
   그룹 목록/상세 화면 자체는 이번 목업 범위 밖 (필요 시 목록=full-width, 상세=2열 4:8로 확장)
5. **수신거부 표시** — 상태 값(빨간 점)과 상태 카드의 수신거부 여부 필드 이중 표기

## 미포함 (PRD상 후속)

- 크리에이터 정합성 일괄 검증 화면 (보류 큐) — 목록 패턴 + 등급 필터로 확장 예정
- 캠페인 메일 발송(P2)
